# Репозиторий и отчёты студента

Решения размещаются в `solutions/` вашего публичного форка, а не в репозитории преподавателя. Для ЛР №1 репозиторий не требуется; начиная с ЛР №2 ведите историю небольших осмысленных коммитов.

## Структура результата

```text
<корень-вашего-форка>/
├── .github/workflows/ci.yml       # Учебный CI, добавляется в ЛР №6
└── solutions/
    ├── assist-py/                # Приложение для ЛР №2–6
    │   ├── README.md
    │   ├── Dockerfile
    │   └── k8s/                  # Манифесты начиная с ЛР №5
    └── ЛРN_Фамилия_ИО_ИСУ.pdf     # Копия отчёта начиная с ЛР №2
```

Используйте ветку `lab-N` для соответствующей работы. README приложения должен описывать запуск, проверку результата и изменения по мере прохождения Compose, Kubernetes и CI/CD.

## Отчёты

Имя файла: `ЛРN_Фамилия_ИО_ИСУ.pdf`, например `ЛР2_Иванов_ИА_408145.pdf`. Основной PDF загрузите в свою папку на учебном диске, копию для ЛР №2–6 положите в `solutions/`; полный порядок описан в [сдаче и защите](../syllabus/submission.md).

## Образцы

Используйте [образец README приложения](_template/README.md). Пример исключений Git приведён ниже; такой же файл хранится в `_template/.gitignore` для копирования в свой проект.

```gitignore
.env
.env.*
!.env.example
**/k8s/app-secret.yaml
__pycache__/
*.pyc
.venv/
venv/
.DS_Store
```

## Что не публиковать

Не добавляйте настоящие пароли, токены, приватные ключи, Kubernetes `node-token` и рабочие `.env`. В примерах и скриншотах заменяйте реальные секреты безопасными значениями; раскрытый секрет нужно заменить, одного удаления файла недостаточно.
