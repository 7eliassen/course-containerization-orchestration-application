# Работы в личном форке

Все результаты, начиная с ЛР №1, хранятся в `solutions/` вашего форка. В репозиторий преподавателя работы не переносятся; платформа содержит ссылки на сдачу, а не копии файлов с общего диска.

## Структура

```text
<корень-вашего-форка>/
├── .github/workflows/ci.yml           # Учебный CI для ЛР №6
└── solutions/
    ├── reports/
    │   ├── lab-1/
    │   │   ├── ЛР1_Фамилия_ИО_ИСУ.pdf
    │   │   ├── main.tex
    │   │   ├── Paper.tex
    │   │   ├── gost.sty
    │   │   └── step-01.png           # Собственный скриншот, если нужен
    │   └── lab-2/                    # И аналогично lab-3…lab-6
    └── assist-py/                    # Приложение начиная с ЛР №2
        ├── README.md
        ├── Dockerfile
        └── k8s/                      # Начиная с ЛР №5
```

Исходники отчёта состоят из трёх файлов шаблона и собственных добавленных материалов. Ветка `lab-N` фиксирует и отчёт, и соответствующую версию приложения; для ЛР №1 приложение не требуется, но отчёт в репозитории обязателен.

## Работа с ветками

Первую работу выполняйте в `lab-1`. Для следующих работ создавайте новую ветку от результата предыдущей и сохраняйте прежние отчёты; ссылку на ветку и конкретный коммит сдачи размещайте на платформе вместе со ссылкой на PDF.

Пример README приложения находится в [ЛР №2](../labs/02-docker-image.md). Порядок отправки результата приведён в [сдаче и защите](../syllabus/submission.md), оформление в [инструкции LaTeX](../materials/report-format.md).

## Временные файлы и секреты

Не публикуйте реальные пароли, токены, приватные ключи, Kubernetes `node-token`, рабочие `.env`, виртуальные окружения и зависимости. В отчётах и скриншотах используйте безопасные примеры; раскрытый секрет нужно заменить, одного удаления из текущего файла недостаточно.

PDF, `main.tex`, `Paper.tex`, `gost.sty` и собственные изображения нужно коммитить. Временные файлы компиляции `.aux`, `.log`, `.toc`, `.out`, `.fls`, `.fdb_latexmk` и `.xdv` уже исключены правилами корневого `.gitignore`.
