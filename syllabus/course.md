# Контейнеризация и оркестрация приложений

Осень 2026. Преподаватель: Аминов Натиг Сабит оглы.

## Цель курса

Научиться упаковывать приложения в контейнеры, описывать многосервисные системы и запускать их в кластере Kubernetes с автоматической сборкой.

## Результаты обучения

После завершения курса студент умеет:

- [ ] собирать образ Docker и запускать контейнер с настройкой через переменные окружения;
- [ ] оптимизировать Dockerfile, настраивать проверку здоровья и тегировать образы;
- [ ] хранить данные вне контейнера и настраивать сети между контейнерами;
- [ ] описывать многосервисное приложение в Docker Compose и масштабировать сервисы;
- [ ] разворачивать приложение в Kubernetes манифестами и настраивать CI/CD на кластере из нескольких узлов.

## Как сдать лабораторную работу

Каждая лабораторная работа — ключевая контрольная точка: её нужно сдать хотя бы на минимальный балл для закрытия дисциплины.

1. Сделайте публичный форк (`Fork`) этого репозитория курса.
2. Выполняйте работы в каталоге `solutions/` вашего форка и делайте коммиты, демонстрирующие работу, а также README с инструкцией по воспроизводимости. Для ЛР №1 репозиторий не нужен.
3. Подготовьте отчёт в формате **PDF** по разделу «Формат сдачи» в тексте работы (имя файла `ЛРN_Фамилия_ИСУ.pdf`).
4. В папке «Отчеты КонОркПрил Осень 2026/27 ФПИн» создайте папку по своим ФИО (например, «Аминов Натиг Сабит оглы»), в ней — папку с номером работы («Лабораторная 1») и загрузите туда PDF-отчёт. Копию отчёта также кладите в `solutions/`.
5. Защититесь на занятии. Запись на защиту — через платформу.

Защита проходит в форме доклада обучающегося по выполненной работе и ответов на вопросы преподавателя. Если оформление отчёта и доклад соответствуют требованиям, обучающийся получает максимальный балл.

### Основания для снижения баллов

- неполное соответствие техническому заданию;
- неверный выбор языковых средств;
- плохой стиль написания программы;
- небрежное выполнение;
- низкое качество графического материала (при необходимости);
- защита лабораторной после отведённого срока.

### Основания для доработки отчёта

- серьёзное несоответствие техническому заданию;
- некорректная работа программы;
- отсутствие необходимых разделов;
- отсутствие необходимого графического материала (при необходимости);
- некорректная обработка результатов измерений.

## Политики курса

**Дедлайны**

Расписание дедлайнов по каждой работе указано на платформе. Если работа загружена после дедлайна, штраф — минус 2 балла за защиту после дедлайна. В случае выходных, праздников или отмены занятия по вине преподавателя дедлайн сдвигается.



**Правила общения и защиты**

- Если вы собираетесь писать в личные сообщения, напишите в общий чат. В крайнем случае преподаватель сам переведёт диалог в личные сообщения.
- Если нет отчёта и/или репозитория, вы не защищаетесь.
- Если места на защиту кончились, в этот день вы не защищаетесь.
- Нельзя за один раз (в один день) защитить больше 3 работ.
