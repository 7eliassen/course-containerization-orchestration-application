Подключаем к приложению PostgreSQL, учимся хранить данные вне контейнера и разбираемся с сетями Docker.

## Этап 1. Запуск контейнера с именованным volume

Откройте репозиторий с прошлой работы и создайте от ветки `lab-2` новую ветку `lab-3`:

```bash
git checkout lab-2

```

### Задание 1.1 - Создайте именованный volume для БД

```bash
docker volume create <фамилия>-pgdata
```

Проверьте создание:

```bash
docker volume ls | grep <фамилия>-pgdata
docker volume inspect <фамилия>-pgdata
```

### Задание 1.2 - Запустите PostgreSQL с вашим volume

```bash
docker run -d \
--name <фамилия>-postgres \
-e POSTGRES_USER=user_<цифры> \
-e POSTGRES_PASSWORD=pgpass_<цифры> \
-e POSTGRES_DB=assistant_<цифры> \
-v <фамилия>-pgdata:/var/lib/postgresql/data \
-p <ваш_порт_postgres>:5432 \
postgres:15
```

Проверьте статус:

```bash
docker ps --filter "name=<фамилия>-postgres" --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
```

### Задание 1.3 - Соберите образ приложения (если не сделали в ЛР2)

```bash
docker build -t <фамилия>-assistant:v3 .
```

### Задание 1.4 - Запустите ассистент и подключите к БД

```bash
docker run -d \
--name <фамилия>-assistant \
-p <ваш_порт_ассистента>:<ваш_порт_ассистента> \
-e APP_OWNER=<ваша_фамилия> \
-e APP_SECRET=<ваш_секретный_ключ> \
--add-host=host.docker.internal:host-gateway \
-e DATABASE_URL="postgresql://user_<цифры>:pgpass_<цифры>@host.docker.internal:<ваш_порт_postgres>/assistant_<цифры>" \
<фамилия>-assistant:v3
```

`host.docker.internal` - адрес хоста изнутри контейнера. На Docker Desktop (Mac и Windows) он работает сам, а на Linux нужен флаг `--add-host=host.docker.internal:host-gateway`. В команды ниже он уже добавлен.

## Этап 3. Bind mount для конфигурации

### Задание 3.1 - Изучите файл конфигурации

В папке config/ лежит файл app.conf:

```ini
# Конфигурация персонального ассистента
max_notes_per_user=100
enable_weather_api=true
maintenance_mode=false
owner=<ваша_фамилия>
```

### Задание 3.2 - Создайте контейнер с bind mount

```bash
docker run -d \
--name <фамилия>-assistant-config \
-p <ваш_порт_ассистента>:<ваш_порт_ассистента> \
-e APP_OWNER=<ваша_фамилия> \
-e APP_SECRET=<ваш_секретный_ключ> \
--add-host=host.docker.internal:host-gateway \
-e DATABASE_URL="postgresql://user_<цифры>:pgpass_<цифры>@host.docker.internal:<ваш_порт_postgres>/assistant_<цифры>" \
-v $(pwd)/config:/app/config:ro \
<фамилия>-assistant:v3
```

Пояснение флага -v:

1. (pwd)/config - папка на хосте
2. /app/config - папка внутри контейнера
3. :ro - read-only (контейнер не может изменить файлы)

### Задание 3.3 - Проверьте доступ к конфигурации

```bash
# Зайдите в контейнер
docker exec -it <фамилия>-assistant-config sh
# Внутри контейнера:
cat /app/config/app.conf
# Выйдите
exit
```

Требуется в отчёте установить скриншот вывода cat /app/config/app.conf внутри контейнера. В файле должна быть видна ваша фамилия в поле owner.

Микро-челлендж: измените конфиг без пересборки:

1. Откройте config/app.conf на хосте
2. Измените maintenance_mode=true
3. Перезапустите контейнер: docker restart `<фамилия>`-assistant-config
4. Проверьте, что файл внутри контейнера обновился: docker exec `<фамилия>`-assistant-config cat /app/config/app.conf

## Этап 4. Пользовательские сети для изоляции

### Задание 4.1 - Создайте пользовательскую сеть

```bash
docker network create <фамилия>-backend
```

### Задание 4.2 - Пересоздайте контейнеры в пользовательской сети

```bash
# Остановите старые контейнеры
docker stop <фамилия>-postgres <фамилия>-assistant-config
docker rm <фамилия>-postgres <фамилия>-assistant-config
# Запустите БД в пользовательской сети
docker run -d \
--name <фамилия>-postgres \
--network <фамилия>-backend \
-e POSTGRES_USER=user_<цифры> \
-e POSTGRES_PASSWORD=pgpass_<цифры> \
-e POSTGRES_DB=assistant_<цифры> \
-v <фамилия>-pgdata:/var/lib/postgresql/data \
postgres:15
# Запустите ассистент в той же сети
docker run -d \
--name <фамилия>-assistant \
--network <фамилия>-backend \
-p <ваш_порт_ассистента>:<ваш_порт_ассистента> \
-e APP_OWNER=<ваша_фамилия> \
-e APP_SECRET=<ваш_секретный_ключ> \
-e DATABASE_URL="postgresql://user_<цифры>:pgpass_<цифры>@<фамилия>-postgres:5432/assistant_<цифры>" \
-v $(pwd)/config:/app/config:ro \
<фамилия>-assistant:v3
```

Ключевое изменение: Теперь DATABASE_URL использует имя контейнера `<фамилия>`-postgres вместо host.docker.internal. Docker DNS автоматически разрешает имена контейнеров в одной сети!

### Задание 4.3 - Проверьте связность

```bash
# Проверка работоспособности
curl http://localhost:<ваш_порт_ассистента>/health
# Создайте новую заметку
curl -X POST http://localhost:<ваш_порт_ассистента>/notes \
-H "Content-Type: application/json" \
-d '{"text": "ЛР3: сеть работает!"}'
# Получите все заметки
curl http://localhost:<ваш_порт_ассистента>/notes
```

### Задание 4.4 - Исследуйте сетевую изоляцию

```bash
# Запустите временный контейнер вне сети
docker run -it --rm alpine:3.18 ping -c 2 <фамилия>-postgres
# Запустите временный контейнер ВНУТРИ сети
docker run -it --rm --network <фамилия>-backend alpine:3.18 ping -c 2 <фамилия>-postgres
```

Вставьте в отчет скриншоты обоих ping команд - первый с ошибкой, второй с успешным ответом.
