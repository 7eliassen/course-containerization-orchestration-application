## Общие правила

- Каждую лабораторную делаем в своей ветке `lab-N`, которую создаём от ветки прошлой работы.
- В репозитории лежат `Dockerfile`, `docker-compose.yml`, каталог `k8s/` (ЛР №5 и №6) и `.github/workflows/` (ЛР №6).
- Файлы с настоящими паролями (`.env`, `k8s/app-secret.yaml`) в git не кладём, добавляем в `.gitignore`.
- Отчёт называем `ЛРN_Фамилия_ИСУ.pdf`.

## Оформление репозитория

В ЛР №1 репозиторий не нужен, сдаётся только PDF-отчёт.

Начиная с ЛР №2 каждая работа сдаётся через репозиторий на GitHub (ветка `lab-N`) и PDF-отчёт со ссылкой на него. Требования к содержимому репозитория описаны в каждой лабораторной, образец README есть в ЛР №2 и в файле [../solutions/_template/README.md](../solutions/_template/README.md). Пароли, `.env` и токены в репозиторий не попадают.

## Где вести работу

ЛР №1 делается без репозитория, сдаётся только PDF-отчёт. Начиная с ЛР №2 вы ведёте публичный форк этого репозитория; проект `assist-py` лежит в `solutions/assist-py/`, каждая работа — в отдельной ветке `lab-N`, созданной от ветки прошлой работы. Копии PDF-отчётов кладутся в `solutions/` (подробнее — [решения](../solutions/README.md)). Шаблон новой работы — [00-template.md](00-template.md).
