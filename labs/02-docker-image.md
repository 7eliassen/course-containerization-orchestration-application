Создайте файл Dockerfile в корне проекта. Он должен содержать:


Подсказки:

<details>
<summary>Подсказки к Dockerfile</summary>

Чтобы не менять порт в нескольких местах, задайте `ENV PORT=<ваш_порт>` и дальше используйте `${PORT}` (в `EXPOSE`, `CMD` и `HEALTHCHECK`).

Запускайте через shell-форму: `CMD uvicorn app.main:app --host 0.0.0.0 --port ${PORT}`. В виде списка `CMD ["uvicorn", ...]` переменная не подставится.

</details>

## Этап 4. Healthcheck - готовность к оркестрации

### Задание 4.1 - Добавьте проверку здоровья

В конец Dockerfile.optimized (после EXPOSE) добавьте:

```bash
RUN apt-get update \
    && apt-get install -y --no-install-recommends curl \
    && rm -rf /var/lib/apt/lists/*

HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
CMD curl -f http://localhost:${PORT}/health || exit 1
```

В `python:3.11-slim` нет curl, поэтому ставим его через `apt-get`. Без него healthcheck будет падать и статус `healthy` не появится.

Вопрос: на сколько МБ вырос образ после установки curl? Сравните `docker images` до и после. Как можно было обойтись без curl?

Пояснение флагов:

--interval=30s - проверять каждые 30 секунд

--timeout=5s - ждать ответа не дольше 5 секунд

--start-period=10s - дать контейнеру 10 секунд на «прогрев» после старта

--retries=3 - считать сервис нездоровым после 3 неудачных проверок

### Задание 4.2 - Соберите финальную версию

```bash
docker build -t <фамилия>-assistant:final -f Dockerfile.optimized .
```

### Задание 4.3 - Проверьте статус здоровья

```bash
# Запускаем контейнер
docker run -d \
--name <фамилия>-assistant-final \
-p <ваш_порт>:<ваш_порт> \
-e APP_OWNER=<ваша_фамилия> \
-e APP_SECRET=<ваш_секретный_ключ> \
<фамилия>-assistant:final
# Ждём инициализацию (10 секунд)
sleep 10
# Проверяем статус - должен быть (healthy)
docker ps --filter "name=<фамилия>-assistant-final" --format "table {{.Names}}\t{{.Status}}"
```

В отчет добавьте скриншот вывода docker ps, где чётко виден статус (healthy).
